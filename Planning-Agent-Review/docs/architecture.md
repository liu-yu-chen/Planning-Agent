# 系统架构与模块职责

## 分层结构

1. **连接器层**负责与外部书目服务通信、分页、限速、重试和断点续传。它不决定研究范围，也不保存长期凭证。
2. **数据规范层**把来源差异映射到统一文献结构，保留来源 ID、时间戳和原始字段，以支持溯源与重新处理。
3. **索引层**从规范化语料派生全文、向量和关系索引。索引可删除并重建，因此与源代码和原始输入分开存储。
4. **检索层**将问题路由到适当的检索器，合并候选、去重并构建有限上下文。每项证据都保留可引用的来源标识。
5. **Agent 层**解析问题、决定工具调用、整合检索结果，并要求模型区分有证据支持的结论与信息缺口。
6. **交互与部署层**管理会话、配置和本地运行服务。桌面启动器只负责启动 UI 与模型服务，不改变研究数据。

## 数据流

一次研究问题从界面进入 Agent，经查询改写后进入本地索引；需要新近信息时，外部网页检索也作为该轮证据链的一部分。检索器返回结构化候选及来源信息；证据融合层控制上下文规模并合并重复记录；生成器收到用户问题、证据和引用规则后撰写答复。回答与来源列表一同呈现，供研究者核查。

## 可替换边界

模型服务、书目连接器、嵌入模型、索引实现和 UI 通过模块接口隔离。替换其中一层时，应保持规范文献结构、来源标识和检索返回格式稳定。凭证只在需要发出外部请求的连接器边界读取。
